AI sandbox configuration
========================

The Codex sandbox runs in a constrained, non-interactive environment. Use the
prerequisite installer to standardize local tooling and avoid manual package
management during automated runs.

Sandbox checklist
-----------------

- Start in the repository root and run `./install.sh --mode dev`. The older
  `./bootstrap.sh` and `./scripts/install_prerequisites.sh` paths remain
  available as compatibility wrappers when existing automation still calls
  them.
- Allow the managed flow to create `.venv`; it provisions the configured
  bootstrap/runtime contexts, upgrades packaging tools, installs mdview
  through `scripts/install_project.py`, and installs repo-local workflow
  helpers.
- On Unix-like hosts, development mode provisions user-scoped pyenv
  selections and expects `direnv`. Supported Linux flows can install a
  user-local `direnv` binary automatically when it is missing.
- Non-interactive development installs leave PATH resolution unchanged by
  default; set `MDVIEW_DEV_LAUNCHER_MODE=local` or
  `MDVIEW_DEV_LAUNCHER_MODE=system` when the desired launcher behavior must
  be explicit.
- Run follow-up repository commands with `.venv/bin/python` or activate
  `.venv` before using `python`.
- Keep the working directory clean: the installer avoids global changes and
  prefers the project-local virtual environment.
- Use `--force-direct-run` with `scripts/install-stage-2.py` only for
  explicit debugging. Example:
  `python scripts/install-stage-2.py --force-direct-run --mode venv-only`.

Platform notes
--------------

- Rocky Linux/Fedora: installer uses `dnf` or `yum` with `sudo` when
  available.
- Ubuntu/Debian/Mint: installer runs `apt-get update` followed by package
  installation with `-y` for unattended runs.
- macOS: installer expects Homebrew; ensure `brew` is on `PATH` before
  running in the sandbox.

Failure handling
----------------

- When `sudo` is unavailable, run the script as a privileged user or install
  the prerequisites manually, then rerun the installer.
- If the platform is unsupported, the Python script exits with a clear error.
  CI jobs can fail fast.
