Human orders for AI agents
==========================

Use the following command phrases in prompts to direct AI agents that follow
`AGENTS.md`:

- Iterate the backlog: Run one cycle from `docs/AI-backlog-iteration.txt` on
  the top item in `/project-management/state/backlog.txt` unless the prompt
  specifies a different target.
- Iterate on the buglist: Apply the backlog-style iteration steps to the top
  entry in `/project-management/state/bugs/known-bugs.txt`, updating the bug
  tracking files with ISO 8601 timestamps when moving items between lists.
- Start bug triage: Review `/project-management/state/bugs/known-bugs.txt` for
  completeness, reproductions, owners, and timestamps. Reorder or prune items
  as needed while preserving the oldest entries at the bottom.
- Start work on <item>: Move the named backlog or bug entry into the relevant
  in-progress file, adding the current ISO 8601 timestamp and owner details.
- Resolve <item> or close <item>: Move the named task into the corresponding
  completed file, or move the named bug into
  `/project-management/state/bugs/resolved-bugs.txt` with a timestamp,
  `Root cause:` analysis, and concise `Resolution:` notes.
- Verify Windows shims from Linux: run
  `.venv/bin/python scripts/run_tool_with_timeout.py windows_shims_linux`,
  summarize whether local paths returned PASS or SKIP, and confirm Windows CI
  still acts as the authoritative gate.
- Verify Linux workflow from Windows WSL2: run the WSL2 wrapper workflow only
  from a real Windows host, summarize PASS/SKIP/FAIL, and confirm Linux CI
  remains the authoritative compatibility gate.
- Review AI-human requests: inspect
  `/project-management/state/ai-human-requests.txt`, add any newly discovered
  operator actions to `Pending Requests`, and report likely-complete entries
  that still need human confirmation before closure.

When issuing these orders, provide context, acceptance criteria, and any
constraints so the agent can complete the cycle without unnecessary
clarification. All updates must retain the asterisk-plus-blank-line formatting
used throughout the project management and bug-tracking files.
