Installation strategy
=====================

Use `install.sh` as the canonical POSIX bootstrap entry point. The shell
wrapper locates or installs a bootstrap Python 3.9+ interpreter and then
delegates the main setup work to `scripts/install-stage-2.py`.

mdview uses three install modes:
- default standard mode: user-local non-development install;
- `--mode dev`: repo-local development install with `.venv`; and
- `--mode venv-only`: repo-local toolchain refresh without reinstalling
  mdview itself.

The legacy `bootstrap.sh` and `scripts/install_prerequisites.sh` entry points
remain available as compatibility wrappers to `install.sh`. Windows users
should continue to use the PowerShell and cmd bootstrap shims under
`scripts/windows/`.

Quick start
-----------

From the repository root:

```
./install.sh
```

That default is a user-local non-development install. For repository
development, use:

```
./install.sh --mode dev
```

When you only want the managed repo-local toolchain refreshed, use:

```
./install.sh --mode venv-only
```

Supported platforms
-------------------

- Rocky Linux 9.6 (dnf/yum)
- Fedora 43 (dnf)
- Ubuntu 24.x (apt)
- Linux Mint (apt)
- Debian stable/testing (apt)
- Modern macOS releases (Homebrew)

What the installer does
-----------------------

- Detects the platform and chooses an available package manager for the
  bootstrap interpreter when needed.
- Uses standard mode as the default install mode.
- Provisions the configured pyenv bootstrap/runtime selections, writes
  `.python-version`, refreshes `.venv`, and installs repo-local workflow
  helpers for development and venv-only modes.
- Delegates mdview-specific install behavior to `scripts/install_project.py`,
  which installs mdview in editable mode for development, non-editable mode
  for standard installs, and manages the user-facing `mdview` launcher.
- Refreshes the pinned Black/Ruff/pytest toolchain through
  `scripts/dev_setup.py` for repo-local development and venv-only modes.
- Installs or updates managed git hooks through `scripts/install_git_hooks.py`
  for repo-local development and venv-only modes.
- Updates managed shell-init blocks and `.envrc` for development mode, and
  can install a user-local `direnv` binary automatically on supported Linux
  hosts when needed.

Notes and expectations
----------------------

- Run `./install.sh --mode dev` from the repository root when you want the
  repo-local development environment used for tests and linting.
- Development mode reports whether another `mdview` executable appears on
  PATH before prompting whether arbitrary-directory invocations should use
  the checkout-local copy. Non-interactive development installs leave PATH
  resolution unchanged by default; set `MDVIEW_DEV_LAUNCHER_MODE=local` or
  `MDVIEW_DEV_LAUNCHER_MODE=system` when automation must force that choice.
- `sudo ./install.sh` without `--system` must fail with an explanation. Use
  `sudo` only for explicit system installs.
- `./install.sh --system` without root privileges must fail with an
  explanation.
- Source `./set-context-bootstrap.sh` or `./set-context.sh` when you need to
  force the bootstrap or runtime pyenv context explicitly. The checked-in
  `.python-version` file makes the runtime context the default local choice.
- On Unix-like hosts, development mode provisions user-scoped pyenv
  selections and expects `direnv`. Supported Linux flows can install a
  user-local `direnv` binary automatically when needed; other hosts should
  provide `direnv` on PATH already.
- `bootstrap.sh`, `bootstrap-stage2.py`, and
  `scripts/install_prerequisites.sh` remain valid compatibility entry points,
  but new docs and automation should prefer `./install.sh`.
- After development bootstrap, use `.venv/bin/python` for fully explicit
  local-check runs, or activate `.venv` before invoking `python`.
- Use `python scripts/install-stage-2.py --force-direct-run` only for
  explicit debugging of stage-two behavior.
- Entropy-secret checks are wired into managed hooks:
  - `pre-commit` runs entropy checks.
  - `pre-push` runs cached quality-gate checks.
  See `docs/security/entropy-checks.txt` for details and manual run commands.
- Standardized git operation utilities are available after setup:
  - `python scripts/git_standard_commit_push.py -m "<message>"`
  - `python scripts/git_veteran_pull.py`
  - Cache file used by push quality gate: `.git/mdview-quality-cache.json`
  - Runbook: `docs/security/git-tripwire-operations.txt`
