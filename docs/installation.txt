Installation strategy
=====================

Use `scripts/install_prerequisites.sh` as the canonical bootstrap entry point.
The shell wrapper locates or installs Python 3, provisions `.venv` at the
repository root, upgrades packaging tools, and delegates system and Python
package installation to `scripts/install_prerequisites.py`.

Quick start
-----------

From anywhere inside the repository (or via an absolute path):

```
./scripts/install_prerequisites.sh
```

The script defaults to installing mdview in editable mode with development
extras. Pass `--production` through to the Python installer when you want to
skip developer dependencies:

```
./scripts/install_prerequisites.sh --production
```

Legacy forwarding also remains supported:

```
./scripts/install_prerequisites.sh -- --production
```

Interactive command resolution
------------------------------

During interactive POSIX developer installs, the Python installer reports
whether another `mdview` executable appears on PATH outside this checkout and
then asks whether typing `mdview` in arbitrary directories should use the
local development copy or leave PATH resolution unchanged. Choosing the local
development copy installs a managed `~/.local/bin/mdview` shim that delegates
to this checkout's `.venv` entry point.

Override the prompt explicitly when needed:

```
./scripts/install_prerequisites.sh --mdview-command local
./scripts/install_prerequisites.sh --mdview-command system
```

Supported platforms
-------------------

- Rocky Linux 9.6 (dnf/yum)
- Fedora 43 (dnf)
- Ubuntu 24.x (apt)
- Linux Mint (apt)
- Debian stable/testing (apt)
- Modern macOS releases (Homebrew)

What the installer does
-----------------------

- Detects the platform and chooses an available package manager.
- Installs `python3`, `venv` tooling, `less`, and `git` using the native
  package manager (with `sudo` when required).
- Creates `.venv` if missing and upgrades `pip`, `setuptools`, and `wheel`.
- Skips package-manager installation when the required system tools are
  already available.
- Installs the project in editable mode with:
  - `interactive` extras by default in all modes (for `prompt_toolkit` pager),
  - `dev` extras when not using `--production`.
- Installs/updates managed git `pre-commit` and `pre-push` hook wrappers via
  `scripts/install_git_hooks.py`.

Notes and expectations
----------------------

- The installer resolves project root from script location and always installs
  the editable project from that root, regardless of current working
  directory.
- After bootstrap, use `.venv/bin/python` for repository-local checks or
  activate `.venv` before running `python`.
- If the host lacks `sudo`, run the script as a privileged user or install the
  required system packages manually.
- Use `--skip-system-packages` when system dependencies are already present or
  when package-manager access is intentionally restricted.
- The Python logic supports a dry run for validation: `python scripts/
  install_prerequisites.py --dry-run`.
- Entropy-secret checks are wired into managed hooks:
  - `pre-commit` runs entropy checks.
  - `pre-push` runs cached quality-gate checks.
  See `docs/security/entropy-checks.txt` for details and manual run commands.
- Standardized git operation utilities are available after setup:
  - `.venv/bin/python scripts/git_standard_commit_push.py -m "<message>"`
  - `.venv/bin/python scripts/git_veteran_pull.py`
  - Cache file used by push quality gate: `.git/mdview-quality-cache.json`
  - Runbook: `docs/security/git-tripwire-operations.txt`
