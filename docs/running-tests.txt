Running Tests
============

Prerequisites
-------------
- Python 3.9 or newer available on your PATH.
- Run `./install.sh --mode dev` from the repository root before first use in
  a fresh checkout or environment. The legacy `./bootstrap.sh` and
  `./scripts/install_prerequisites.sh` paths remain available as
  compatibility wrappers.
- The managed development flow provisions the configured pyenv
  bootstrap/runtime selections, writes `.python-version`, refreshes `.venv/`
  in the checkout, and installs mdview plus the pinned developer toolchain.
- On Unix-like hosts, development mode expects `direnv`. Supported Linux
  flows can install a user-local `direnv` binary automatically when it is
  missing; other hosts should provide `direnv` on PATH already. Windows
  users should continue to use the PowerShell or cmd bootstrap shims.
- After setup, run commands with `.venv/bin/python` or activate `.venv`
  before using `python`.

Standard test run
-----------------
- Execute the full suite from the repository root:
  - `python scripts/run_tool_with_timeout.py pytest`
- For sanity checks before commits, also run:
  - `python scripts/run_tool_with_timeout.py black`
  - `python scripts/run_tool_with_timeout.py ruff`
  - `python scripts/run_tool_with_timeout.py compileall`
  - `python scripts/run_tool_with_timeout.py entropy_check`
  - `python scripts/run_tool_with_timeout.py entropy_tripwire_verify`
  - `python scripts/run_tool_with_timeout.py demo_check`

Focused execution
-----------------
- To target specific tests while iterating, use `-k` to match a substring:
  - `python scripts/run_tool_with_timeout.py pytest -- -k plain_text`
- To rerun a single file or test function:
  - `python scripts/run_tool_with_timeout.py pytest --`
    `tests/test_rendering.py::`
    `test_render_to_ansi_preserves_five_line_plain_text`

Environment Notes
-----------------
- Tests rely on static fixtures stored under `resources/tests/`. Keep these
  files in sync with their user stories.
- Use UTF-8 when reading fixture files to preserve ASCII compatibility
  guarantees.
- Tool timeouts are configured in `scripts/tool_timeouts.json`. Keep defaults
  short. Increase a timeout only when a shorter value is confirmed to
  interrupt a legitimate run.
- For one-off overrides, pass `--timeout-seconds`, for example:
  `python scripts/run_tool_with_timeout.py pytest --timeout-seconds 300 --`
  `-k nested`
- Windows 11 shell parity wrappers:
  - PowerShell:
    `powershell -ExecutionPolicy Bypass -File scripts/windows/run-tool.ps1`
    `pytest`
  - cmd.exe:
    `scripts\\windows\\run-tool.bat pytest`
- Linux-side Windows shim validation:
  - `python scripts/run_tool_with_timeout.py windows_shims_linux`
  - See `docs/testing/windows/README.txt` for workflow, `SKIP` handling, and
    maintenance notes.
- Windows-side Linux workflow validation via WSL2:
  - Defined in `docs/testing/wsl2/README.txt` and corresponding specification.
  - Execute only on a real Windows host with WSL2; otherwise treat as
    documentation-only planning.
- Entropy-based secret scanning:
  - `python scripts/run_tool_with_timeout.py entropy_check`
  - See `docs/security/entropy-checks.txt` for thresholds, exclusions, and
    managed hook behavior.
- Tripwire integrity verification:
  - `python scripts/run_tool_with_timeout.py entropy_tripwire_verify`
  - Included in the cached quality gate used before push.
- Cached full quality gate (used by standardized push workflow):
  - `python scripts/run_quality_gate_cached.py`
  - Set `MDVIEW_QUALITY_GATE_NO_CACHE=1` or pass `--no-cache` to force an
    uncached rerun.
- Demo-document validation:
  - `python scripts/run_tool_with_timeout.py demo_check`
  - Uses `.git/mdview-demo-validation-cache.json` so unchanged demo files are
    skipped automatically.
