Markdown Inline Code Rendering Specification
==========================================

Scope
-----
Define how mdview renders inline code spans so monospace cues, punctuation, and
spacing remain consistent across renderers. Cover fixture layout, styling
expectations, escape handling, and fallback behavior when monospace rendering is
unavailable.

Assumptions
-----------
- Rendering prefers ``rich.markdown.Markdown`` when available and falls back to
  a plain-text formatter otherwise.
- Source text order and spacing remain unchanged; renderers must not reorder
  characters, collapse whitespace, or inject spacing around markers.
- Tests rely on fixtures under ``resources/tests`` and assert on visible cues
  instead of brittle snapshots.

Rendering Rules
---------------
- Recognize inline code when content is wrapped in paired backticks
  (``\`code\``) without collapsing whitespace inside the markers.
- Emit monospace styling for the enclosed content when the renderer supports it.
  In fallback mode, render the content literally while preserving surrounding
  spacing and punctuation.
- Preserve literal backticks inside code spans when escaped (``\``backtick\```)
  and render unmatched backticks without inferring closures.
- Keep inline code scoped to the smallest matching marker pair and do not allow
  the span to cross paragraph boundaries or swallow neighboring emphasis
  markers.

Whitespace and Spacing Preservation
-----------------------------------
- Do not trim leading or trailing whitespace inside code spans; preserve spaces
  exactly as provided to keep alignment and punctuation intact.
- Maintain the original spacing surrounding code markers so adjacent text,
  commas, and periods remain unchanged in rendered output.
- Keep inline code on a single line; do not merge or break lines around code
  markers during rendering.

Fixture Inventory
-----------------
- ``resources/tests/markdown/inline_code_basic.md``: A sentence with a single
  ``\`code\`` span asserting monospace styling (or literal rendering in
  fallback mode) without altering spacing.
- ``resources/tests/markdown/inline_code_spacing.md``: Exercises leading and
  trailing spaces inside the code span and around punctuation to verify spacing
  preservation.
- ``resources/tests/markdown/inline_code_escape.md``: Uses escaped backticks to
  confirm literal rendering inside and outside code spans without enabling
  monospace styling.
- ``resources/tests/markdown/inline_code_boundary.md``: Places inline code next
  to emphasis markers and at line edges to ensure styling does not leak or
  reorder adjacent content.

Exit Criteria
-------------
- Fixtures above exist and align with the rendering, spacing, and escape rules.
- Renderers apply monospace styling when supported and fall back to literal text
  without altering punctuation or spacing when styling is unavailable.
- Inline code spans remain isolated, preserve interior whitespace, and do not
  merge with adjacent emphasis or punctuation.
