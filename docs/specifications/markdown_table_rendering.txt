Markdown Table Rendering Specification
=====================================

Scope
-----
Define how mdview parses and renders pipe-delimited Markdown tables so that
column boundaries remain visible in both Rich and plain-text fallbacks. The
rules emphasize predictable alignment cues, conservative parsing, and graceful
handling when optional dependencies are missing.
Tables are the primary Markdown exception to viewport-width reflow and may
extend beyond viewport width when minimum column sizing requires it.
Width profile selection semantics are defined in
``docs/specifications/table_width_profile_selection.txt``.

Assumptions
-----------
- Rendering uses ``rich.markdown.Markdown`` when available and falls back to a
  plain-text formatter otherwise.
- Source content may include fenced code blocks; table parsing must not alter
  lines enclosed by fences.
- Only pipe-style tables (``|`` separators plus a header divider) are in
  scope; other table syntaxes remain untouched.

Rendering Rules
---------------
- Detect a table when a line containing ``|`` is followed by a header-divider
  line of dashes and optional colons (e.g., ``| --- |`` or ``:---:``).
- Trim outer pipes and surrounding whitespace from each cell while preserving
  interior spacing.
- Compute column widths from the header, divider, and all subsequent table
  rows until a blank or non-table line appears.
- By default, render recognized tables as boxed grids using Unicode box-
  drawing characters, with border glyphs styled in gray. Border intersections
  must use the appropriate junction characters where outer and cell borders
  overlap.
- Apply table width profile selection using the two-profile model:
  - default ``auto``: fit-first first, readability-first when unavoidable
    overflow remains.
  - ``--readability-first-tables``: force readability-first for table-like
    blocks.
- Support border controls:
  - default: both outer table borders and internal cell borders enabled.
  - ``--no-table-borders``: suppress top, bottom, left, and right borders,
    replacing those positions with whitespace gaps.
  - ``--no-cell-borders``: suppress internal vertical and horizontal cell
    separators, replacing those positions with whitespace gaps.
  - both flags together: render aligned cell content with whitespace gaps
    only.
- Respect alignment markers in the divider row:
  - ``:---`` renders left-aligned cells.
  - ``---:`` renders right-aligned cells.
  - ``:---:`` renders centered cells.
  - Missing or malformed markers default to left alignment.
- Emit padded cell content so that column boundaries remain stable regardless
  of whether borders are visible. When borders are enabled, use boxed-grid
  junction and edge glyphs instead of literal Markdown pipes.
- When a table cell uses inline HTML ``span`` wrappers for color hints,
  preserve the inner text and supported foreground color styling while
  ignoring the wrapper tags for table layout. Those wrappers must not alter
  column sizing or introduce extra vertical gap before a table that appears
  immediately after a heading.
- Leave fenced code blocks unchanged, even if their content resembles a table.
- Do not attempt to merge adjacent tables or reorder rows; process each table
  block independently and preserve original row order.
- Respect minimum readable column widths. If a table cannot fit within the
  current viewport under fit-first rules, switch to readability-first for the
  full table block and keep resulting full width in the rendered virtual
  document.
- Whenever table width exceeds viewport width, horizontal scrolling must be
  active. Left and right arrow keys move the viewport window across the
  table without truncating cell content.

Fallback Behavior
-----------------
- When Rich is unavailable, apply the table formatter before sending
  content to the plain-text renderer so that boxed borders, alignment cues,
  and any visible whitespace gaps remain stable.
- When Rich is available, render table blocks through mdview's custom table
  path instead of depending on Rich's Markdown table parser, because boxed
  border text must not be reflowed back into paragraphs.

Test Coverage
-------------
- Provide fixtures under ``resources/tests`` for at least one table with mixed
  left, right, and centered alignment markers.
- Verify profile selection behavior:
  - ``auto`` chooses fit-first when fit-first fits.
  - ``auto`` chooses readability-first when fit-first cannot fit.
  - ``--readability-first-tables`` forces readability-first.
- Verify that formatted output keeps header and body rows aligned,
  retains cell content verbatim, and does not alter non-table
  paragraphs.
- Verify default boxed output uses the expected box-drawing glyphs.
- Verify border glyphs carry gray styling in framebuffer attributes.
- Verify ``--no-table-borders`` suppresses only the outer border layer.
- Verify ``--no-cell-borders`` suppresses only the internal border layer.
- Add fixtures for a heading immediately followed by a plain Markdown table
  and by an equivalent table whose body cells use ``span``-based color
  wrappers, then compare rendered framebuffers to confirm the heading-to-table
  gap stays the same in both cases.
- Confirm that fenced code blocks containing pipe characters bypass table
  formatting.
