mdview: Console Markdown Viewer Specification
============================================

Purpose
-------
mdview renders Markdown and plain-text documents directly in a terminal
using an internal rendering and viewing engine. The tool preserves
semantic formatting (headings, emphasis, code blocks, lists) with ANSI
styling and provides integrated navigation without outsourcing display
functions to external pagers.

Goals and Non-Goals
-------------------
- Goals
  - Provide a readable, styled Markdown rendering in terminals.
  - Offer integrated navigation: line/page scrolling, search, jump to
    start/end, and horizontal scrolling for overflow content.
  - Remain lightweight with minimal dependencies (Python 3.9+, ``rich``
    for formatting, standard library for CLI).
- Non-Goals
  - Editing or annotating documents.
  - Delegating terminal display to external programs such as ``less`` or
    ``more``.
  - Supporting formats beyond ``.md``, ``.markdown``, and ``.txt`` in the
    initial release.

User Workflow
-------------
1. Invoke ``mdview <path...>`` with one or more files.
2. mdview determines per file whether content is Markdown or plain text.
3. mdview ingests content into the common internal content model using
   the three-pass classification pipeline described in
   ``docs/specifications/unified_content_intake_model.txt``.
4. mdview renders active content with ``rich`` (Markdown markup or plain
   text under the unified reflow policy and reflow-mode semantics).
5. The internal viewer presents rendered content, including vertical and
   horizontal navigation when content exceeds viewport width and
   next/previous document switching in multi-file sessions.

Functional Requirements
-----------------------
- File Handling
  - Accepts files with ``.md`` or ``.markdown`` as Markdown; treats
    ``.txt`` and other extensions as plain text.
  - Reads content using UTF-8 with graceful error messaging on failure.
- Rendering
  - Markdown files: rendered using ``rich.markdown.Markdown``.
    Markdown reflows prose-like blocks to current viewport width by
    default under ``--reflow-mode prose`` semantics.
    ``--reflow`` is redundant for standard Markdown workflows.
    Markdown tables follow two-profile width selection defined in
    ``docs/specifications/table_width_profile_selection.txt`` and may remain
    wider than the viewport when overflow is unavoidable.
  - Plain text (``*.txt``): follows
    ``docs/specifications/plain_text_reflow_behavior.txt``. Default behavior
    preserves source line breaks with no reflow. ``--reflow`` enables
    reflow (defaulting to ``--reflow-mode prose``). ``--noreflow`` or
    ``--reflow-mode none`` disables reflow in all cases.
  - Reflow mode semantics and precedence are defined in
    ``docs/specifications/reflow_mode.txt``.
- Viewing Engine
  - Uses mdview's internal viewer exclusively for display and navigation.
  - Activates horizontal scrolling whenever at least one rendered line
    exceeds viewport width.
  - Uses left and right arrow keys to move the viewport horizontally
    across the rendered virtual document.
  - Supports multi-document sessions with ``n``/``p`` and compatible
    ``:n``/``:p`` commands for next/previous document.
- CLI
  - Command: ``mdview <path...>``.
  - Options: ``--version`` for program version; ``--reflow`` to enable
    reflow processing; ``--noreflow`` to disable reflow; and
    ``--reflow-mode prose|all|none`` to select policy behavior as defined in
    ``docs/specifications/reflow_mode.txt``. ``--readability-first-tables``
    forces readability-first table layout profile selection.
    ``--automation-timeout <seconds>`` injects synthetic quit after a bounded
    viewer runtime for unattended automation.
    ``--automation-timeout-screenshot <basename>`` writes timeout-exit
    artifacts as ``<basename>.txt`` and ``<basename>.attrs.json``, and
    ``--viewport-columns``/``--viewport-rows`` provide synthetic viewport
    size overrides for deterministic automation.
    ``--verbose`` reports document switches, and ``--MIL`` enables
    Monkey-in-the-Loop per-action troubleshooting telemetry.

Quality Attributes
------------------
- Reliability: Clear error messages for missing files, unreadable files,
  or rendering issues.
- Usability: Output should be immediately legible; headings and emphasis
  must stand out, and navigation should remain consistent and predictable.
- Portability: Works on Unix-like systems with Python 3.9+; degrades
  gracefully when optional rendering dependencies are missing.
- Testability: Core formatting and content-loading logic covered by unit
  tests (pytest). CLI behavior validated via smoke tests where feasible.

Dependencies
------------
- Runtime: ``rich`` for Markdown rendering.
- Standard library: ``argparse``, ``pathlib``, and ``typing``.
- Dev/Test: ``pytest`` for unit tests.

Future Enhancements (Out of Scope for Initial Scaffold)
------------------------------------------------------
- Optional themes or custom styling for different terminal backgrounds.
- Syntax highlighting for fenced code blocks using Pygments.
- Inline link rendering improvements (e.g., hiding raw URLs behind link
  text).
- Basic HTML input support by translating HTML tags to terminal styling.
