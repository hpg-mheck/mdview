Security entropy tripwire git workflow
======================================

Status
------
Accepted.

Purpose
-------
Define mandatory entropy-tripwire guardrails for standardized commit/push and
pull operations.

Requirements
------------
1. The project must provide a verifier utility that validates entropy-tripwire
   integrity before push operations continue.
2. The verifier must enforce all of the following:
   - sentinel fixture detection when the fixture is not excluded
   - zero findings after normal harness exclusions are applied
   - scan-count verification against independent repository file enumeration
3. The scanner, harness, and verifier must share default exclusions for
   generated local-environment state that is not repository content,
   including repo-local Codex install directories such as `.codex-home` and
   `.codex-local` when present. Repo-root package-manager lockfiles with
   deterministic integrity hashes, such as `package-lock.json`, must be
   excluded consistently from scanner, verifier, and cached repo-root
   entropy-check fingerprints.
4. The entropy scanner must support a `--json-output` flag that emits a
   machine-readable payload with `schema_version` as the first top-level key.
5. The scanner JSON schema version must be explicit (`1.0.0`) so future
   changes can be version-gated by downstream tooling.
6. A standardized commit/push utility must run the cached quality gate and
   abort before push if any configured check fails.
7. The cached quality gate must persist per-check pass fingerprints in
   `.git/mdview-quality-cache.json`, hashing both relative paths and file
   contents for each check scope while honoring the same generated local
   environment exclusions used by repo-root checks.
8. A standardized pull utility must enforce a guarded pull workflow:
   - clean working tree by default
   - `fetch --all --prune`
   - `pull --ff-only`
   - post-pull entropy check unless explicitly skipped
9. Managed local hooks must include:
   - `pre-commit` entropy scan through timeout wrapper
   - `pre-push` cached quality gate execution
10. Hook installation must preserve existing unmanaged hook behavior by
   wrapping non-managed hooks instead of appending shell content blindly.
11. Setup scripts must install or refresh managed hook wrappers.

Out of scope
------------
- Secret rotation and historical rewrite policies after incident detection.
- Server-side hook enforcement.
