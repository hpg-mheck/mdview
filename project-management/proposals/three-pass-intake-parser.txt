Problem Statement
-----------------
Current parsing behavior does not provide robust, probabilistic
classification for mixed documents. Wide literal structures embedded in prose
can be misclassified, leading to destructive reflow or poor scrolling
decisions. We need a parser that reasons at line, block, and document scope.

Goals
-----
- Implement a three-pass intake parser for all supported file sources.
- Preserve full score vectors for all candidate block types.
- Improve classification via document-level refinement across peer blocks.
- Produce deterministic outputs suitable for deep fixture-driven testing.

Non-Goals
---------
- Defining viewer rendering details or keybinding behavior.
- Replacing DOM contracts established by the DOM proposal.
- Introducing external parsing dependencies that inflate startup cost.

Use Cases
---------
- A plain-text runbook contains prose, fixed-width tables, and divider lines.
- A Markdown file includes code-like sections and table-like regions with
  ambiguous delimiters.
- A long document has repeated structural motifs that should improve
  confidence for ambiguous blocks after global comparison.

Constraints and Assumptions
---------------------------
- Python 3.9+ compatibility and predictable memory usage are required.
- Parser must remain deterministic under identical inputs and options.
- All parsing output must map directly into the unified DOM.

Proposed Approach
-----------------
- Pass 1: line-local feature extraction.
  - Analyze each line independently for width, character classes, spacing
    patterns, delimiter density, and separator likelihood.
  - Emit feature vectors and preliminary hints per line.
- Pass 2: block segmentation and multi-type scoring.
  - Group lines into candidate blocks using pass-1 features plus blank-line
    and separator boundaries.
  - Score each block against every known type (prose, table-like, code-like,
    list-like, heading-like, delimiter-like, and extensible future types).
  - Keep all scores, not only the top candidate.
- Pass 3: document-level refinement.
  - Reweight block scores using document-wide distributions and nearest
    neighbor block similarity.
  - Increase confidence for blocks matching strong recurring patterns; reduce
    confidence for isolated outliers when evidence is weak.
- Emit enriched DOM blocks containing final score vectors, confidence deltas,
  and parser diagnostics.

Risks and Mitigations
---------------------
- Risk: Heuristics overfit fixture data.
  Mitigation: use diverse corpus fixtures and randomized perturbation tests.
- Risk: Performance regressions on large files.
  Mitigation: enforce per-pass budgets and profile-driven guardrails.
- Risk: Classification churn across revisions.
  Mitigation: store and compare pass-level diagnostics in regression tests.

Testing and Validation
----------------------
- Create pass-specific unit tests:
  - Pass-1 feature extraction invariants.
  - Pass-2 segmentation and score-vector completeness.
  - Pass-3 refinement stability and confidence adjustments.
- Add mixed-content fixtures in ``resources/tests`` with expected score bands,
  not brittle exact-value snapshots.
- Run integration checks with reflow policies to verify hard-limit compliance.
  Follow Joel Spolsky's quality bar by validating edge cases before shipping.

Alternatives Considered
-----------------------
- Single-pass parser with immediate classification.
  Rejected because it cannot use global context for ambiguity resolution.
- Two-pass parser without document-level refinement.
  Rejected because repeated-pattern gains are a key requirement.

Open Questions
--------------
- Should pass-3 refinement use fixed rules or a lightweight learned model?
  Owner: Parsing lead. Decision by: 2026-03-28.
- What confidence thresholds should trigger "do not reflow" defaults for
  ambiguous blocks in prose mode? Owner: QA lead. Decision by: 2026-03-28.

- Promote to default after parity checks and policy tests pass.
