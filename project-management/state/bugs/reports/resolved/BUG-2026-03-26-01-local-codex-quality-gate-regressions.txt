BUG-2026-03-26-01
=================

Title
-----
Project-local Codex takeover exposed quality-gate mismatches in the live
tooling environment.

Status
------
Resolved on 2026-03-26T12:13:06-07:00 by Codex (GPT-5.4).

Summary
-------
Taking over the repository from a project-local Codex install exposed two
quality-gate mismatches that were not part of the intended feature work:
- the configured `black` command used `--no-cache`, which the available local
  Black build rejected, and
- the entropy scanner and tripwire verifier treated repo-local Codex managed
  state (`.codex-home/`, `.codex-local/`) as repository content.
- the cached quality-gate fingerprint step also walked repo-local Codex state,
  so transient files under `.codex-home/` could break the standardized
  commit/push path before the actual checks ran.

Symptoms
--------
- `python scripts/run_tool_with_timeout.py black` failed immediately with
  `No such option: --no-cache`.
- `python scripts/run_tool_with_timeout.py entropy_check` flagged
  `.codex-home/.codex/auth.json` and `.codex-local/package-lock.json`.
- `python scripts/run_tool_with_timeout.py entropy_tripwire_verify` failed
  because the harness no longer produced a clean post-exclusion scan.
- `python scripts/git_standard_commit_push.py ...` failed inside
  `scripts/run_quality_gate_cached.py` when fingerprinting a transient lock
  file under `.codex-home/.mozilla/.../lock`.

Root cause
----------
- `scripts/tool_timeouts.json` encoded a `black` command that depended on an
  unsupported flag in the live local formatter installation.
- The entropy scanner and verifier excluded common caches and virtual
  environments but did not exclude generated repo-local Codex state created by
  `codex-wrangler`.
- `scripts/run_quality_gate_cached.py` used a separate root-scope exclusion
  list that also omitted repo-local Codex generated state.

Resolution
----------
- Removed `--no-cache` from the configured `black` command and updated the
  regression assertion in `tests/test_entropy_harness.py`.
- Extended the accepted entropy-tripwire specification and operator-facing
  entropy documentation to treat repo-local Codex state as generated local
  environment data rather than repository content.
- Updated `dev-utils/security/entropy-check.py` and
  `dev-utils/security/verify_entropy_tripwire.py` to exclude `.codex-home`,
  `.codex-local`, `bin/codex-local`, and
  `README-LOCAL-Start-Codex.md`.
- Updated `scripts/run_quality_gate_cached.py` to honor the same local-Codex
  exclusions when fingerprinting repo-root checks.
- Added regression coverage in `tests/test_entropy_harness.py`,
  `tests/test_run_quality_gate_cached.py`, and
  `tests/test_verify_entropy_tripwire.py`.

Validation
----------
- Wrapper-based `ruff`, `compileall`, `entropy_check`,
  `entropy_tripwire_verify`, and full `pytest` passed.
- Wrapper-based `black` passed with the corrected command when executed in the
  operator-approved out-of-sandbox path for this Codex session.
- `python scripts/run_quality_gate_cached.py --checks entropy_tripwire_verify`
  passed against the live repository in the approved out-of-sandbox path.
- Final full-suite result: `306 passed in 3.38s`.

Operator impact
---------------
The feature branch can now validate cleanly in the project-local Codex setup
without false entropy failures from generated local tooling state, and the
configured `black` command no longer depends on a formatter option that is not
available in the live environment. The standardized commit/push cache path now
avoids repo-local Codex lockfiles instead of failing before the real checks
run.
